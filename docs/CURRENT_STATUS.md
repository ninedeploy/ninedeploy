## How to read status

- **Implemented:** a mounted route, producer or client uses the implementation.
- **Locally verified:** the recorded tests or local runtime checks passed for the stated source.
- **Hosted accepted:** a named workflow passed its stated cohort on the named commit.
- **Published:** a release workflow promoted that commit and its artifacts. This does not establish which version an operator runs.
- **Restricted:** stated conditions still apply. An implemented or published feature may remain restricted.

Do not turn one accepted scenario into a claim about every fault timing, runtime or environment. Live agent capability checks and job-time preflight remain authoritative.

## Operational switches and live checks

- `NINEDEPLOY_NODE_SLEEP_AUTOMATION=on` is the panel default; `off` pauses automatic node sleep/wake. The capability API reports this condition. The source test boots the real sleeper plugin with both settings and compares its observer registration with the API answer.
- `NINEDEPLOY_AGENT_PROXY_TRAFFIC=on` is agent opt-in. Agent-advertised operations, not an assumed version number alone, decide support. Update hints in the capability registry do not bypass missing operations or a node owner's switches.
- Node sleep requires an ordinary Docker runtime, active routed domains, bounded verified idle coverage, and no conflicting deployment/lifecycle/canary/fan-out authority. Wake settles only after readiness and loaded routing checks. A held or unknown state is not a completion.
- Database upgrade and PITR option endpoints provide the current resource's actual eligibility. The generated matrix describes structural eligibility; engine state, disk, credentials, ownership and active operations still run through their existing preflights.
